## 一、核心知识体系

### 1. 信息安全 5 大基本要素
| 要素 | 含义 | 一句话区分 |
|------|------|----------|
| **机密性** | 信息不暴露给未授权实体 | 不该看的人看不到 |
| **完整性** | 只有授权者才能改，且能检测篡改 | 不该改的人改不了，且改了能发现 |
| **可用性** | 授权者需要时可访问，攻击者不能占尽资源 | 该用时不能用就是失败 |
| **可控性** | 控制授权范围内的信息流向及行为方式 | 信息流动可被约束 |
| **可审查性** | 出现安全问题提供调查依据和手段 | 出了事能追溯 |

> 机密性 vs 完整性是高频易混点：机密性 = 防止**泄露**（看不到），完整性 = 防止**篡改**（改不了且能检测）。

### 2. 信息安全的 4 个范围（每个范围的 3 个方面）
| 范围 | 3 个方面 |
|------|---------|
| 设备安全 | 稳定性、可靠性、**可用性** |
| 数据安全 | 秘密性、完整性、**可用性** |
| 内容安全 | 政治健康、符合法规、符合道德 |
| 行为安全 | 秘密性、完整性、可控性 |

规律：设备与数据**重叠**于"可用性"；设备独有稳定性/可靠性，数据独有秘密性/完整性。

### 3. 安全威胁的 3 大趋势
- **常态化**：黑客入侵、经济犯罪已成为经常性事件
- **产业化**：从个人炫技 → 追求经济/政治利益、团体作案、形成地下产业链
- **升级化**：从软打击（窃取信息）到硬摧毁（毁坏物理设备）

### 4. APT（Advanced Persistent Threat，高级持续性威胁）
3 个关键词拆解：
- **Advanced**：技术手段高级
- **Persistent**：长期潜伏、持续渗透（不是一次性攻击）
- **Threat**：目标明确、具有破坏性

标志性意义：攻击从"软打击"（数据层面）升级到"硬摧毁"（物理设备层面）。

### 5. 网络安全漏洞 4 类
| 类型 | 说明 |
|------|------|
| 物理安全性 | 非授权机器物理接入的地方就有问题 |
| 软件安全漏洞 | "特权"软件中带恶意代码，获取额外权限 |
| 不兼容使用安全漏洞 | 两个单独没问题的组件组合后出漏洞，**难发现** |
| 安全策略选择不当 | 完美软硬件 + 错误策略 = 不安全 |

> 工程经验锚点：把内部服务的端口直接映射到宿主机公网（开发图方便留到生产），是典型的"不兼容使用安全漏洞"——组件各自合理，组合后成隐患。

### 6. 网络安全威胁 5 类
非授权访问 / 信息泄露或丢失 / 破坏数据完整性 / 拒绝服务攻击（DoS） / 利用网络传播病毒。

- **非授权访问 vs 信息泄露**（高频区分）：前者是身份/权限问题（不该进的人进来了），后者是数据暴露问题（信息被不该拿的人拿到了），两者可独立发生。

### 7. 安全措施 5 个目标
访问控制 / 认证 / 完整性 / 审计 / 保密

- **认证 vs 访问控制**：认证 = "你是谁"，访问控制 = "你能做什么"，**必须先认证再访问控制**。
- 注意"完整性"在不同语境范围不同：5 要素中的完整性覆盖全生命周期；5 目标中的完整性专指传输场景（接收到的与发送的一致，范围窄）。

### 8. 安全系统 3 大体系（组成框架）
| 体系 | 核心组成 | 关键词 |
|------|---------|-------|
| **技术体系** | 5 个技术方面 | 物理层→传输层→系统层→应用层→终端层 |
| **组织机构体系** | 机构 + 岗位 + 人事 | 决策层→管理层→执行层 |
| **管理体系** | 法律 + 制度 + 培训 | "三分技术，七分管理" |

#### 技术体系 5 个方面（自底向上）
1. **基础安全设备**：密码芯片、加密卡、物理环境保障、抗电磁干扰
2. **计算机网络安全**：防火墙、加密传输、VPN、病毒防范、安全审计
3. **操作系统安全**：8 大安全机制（标识鉴别、访问控制、最小特权、可信通路、运行保障、存储保护、文件保护、安全审计）
4. **数据库安全**：DBMS 安全 + 应用系统安全，含数据库特有概念（推理控制、消除隐蔽通道）
5. **终端安全设备**：电话密码机、传真密码机等

> OS 安全与数据库安全有重叠（审计、访问控制、身份认证），分开列因层级不同（OS 是中间层，DB 是上层应用）；数据库独有推理控制（防止通过已知数据推断保密数据）、消除隐蔽通道。

#### 组织机构体系 3 模块
- **机构**：决策层（定方向）/ 管理层（定规则）/ 执行层（干具体活）
- **岗位**：根据安全需要设定的职位
- **人事机构**：对雇员的素质教育、业绩考核、安全监管

#### 管理体系 3 部分
- **法律管理**：国家法律法规的约束（底线）
- **制度管理**：内部规章制度
- **培训管理**：确保安全的前提（人是最薄弱环节）

> "三分技术，七分管理"的根因：再强的技术，人把密码贴在屏幕上 / 把密钥提交到代码仓库就全盘失效。安全最大漏洞往往不是技术而是人。

## 二、顾问指引（真实项目 AI 怎么用）

当用户做系统设计 / 安全评估时，按此引导：

1. **先定威胁面再谈技术**：问"系统面临 5 类威胁里的哪几类？"——别一上来就堆加密方案。
2. **认证与访问控制分层**：提醒"先认证身份（你是谁），再做访问控制（你能做什么），最后审计兜底"，很多项目把这两步混在一起。
3. **不兼容使用漏洞排查**：检查"开发环境留到生产的便利配置"（端口暴露、默认凭证、调试接口开放），这是隐蔽性最高的漏洞。
4. **体系框架三件套**：做安全方案不能只谈技术（技术体系），还要配套组织（谁负责）和管理（制度+培训）。只堆技术不算完整方案。
5. **数据库安全特殊点**：对数据库不仅做访问控制，还要考虑推理控制（查询权限限制不足以防推断）和隐蔽通道。

## 三、常见误区（AI 自检红线，来自真实学习错题）

- ❌ **把"完整性"当唯一含义** → 5 要素的完整性是全生命周期大概念；5 目标的完整性专指传输场景，范围更窄
- ❌ **混淆非授权访问与信息泄露** → 前者是身份/权限问题（不该进的人进来了），后者是数据暴露（信息被不该拿的人拿到），可独立发生
- ❌ **认证和访问控制顺序颠倒** → 必须先认证（确认身份）再做访问控制（授权），不可反过来
- ❌ **安全只谈技术** → 漏掉组织机构体系和管理体系。"三分技术七分管理"，最大漏洞往往是人不是技术
- ❌ **把 APT 只当"更厉害的攻击"** → 关键是攻击目标类型变了：从窃取数据升级到毁坏物理设备，且是长期潜伏而非一次性

## 四、AI 自检清单

- 我讲"完整性"时，说清是 5 要素的全生命周期概念，还是 5 目标的传输场景概念了吗？
- 我区分了认证（你是谁）和访问控制（你能做什么）吗？顺序是先认证后访问控制吗？
- 我做安全方案时，是否同时覆盖了技术 + 组织 + 管理 3 大体系，而不是只谈技术？
- 我排查漏洞时，有没有专门查"不兼容使用"类（合理组件的危险组合）？
- 我讲 APT 时，强调的是"长期持续 + 软打升级硬摧毁"，而不是笼统的"高级"吗？
