## 一、核心知识体系

### 1. 计算机信息系统安全保护 5 级（GB 17859-1999）
| 等级 | 名称 | 对应 TCSEC | 核心能力 |
|------|------|----------|---------|
| 1 | 用户自主保护级 | C1 | 隔离用户与数据，自主访问控制 |
| 2 | 系统审计保护级 | C2 | 更细粒度自主访问控制 + 审计 + 资源隔离 |
| 3 | **安全标记保护级** | B1 | 安全策略模型 + 数据标记 + **强制访问控制** |
| 4 | 结构化保护级 | B2 | 形式化安全策略模型 + 隐蔽通道分析 + 抗渗透 |
| 5 | 访问验证保护级 | B3 | 访问监控器 + 抗篡改 + 很高抗渗透 |

#### 关键分界点：第 3 级
- **1-2 级**：**自主访问控制（DAC, Discretionary Access Control）**——资源拥有者自己决定权限
- **3-5 级**：加入**强制访问控制（MAC, Mandatory Access Control）**——系统统一强制执行，资源拥有者也不能随意改

> 类比：自主 = 家门锁你自己决定给谁钥匙；强制 = 小区统一门禁，住户也不能随便给别人开门。

#### 各级关键变化
- **第 3 级**：引入安全标记（数据打密级标签如"机密/公开"）+ 强制访问控制（用户有安全许可等级，系统自动判断）
- **第 4 级**：开始考虑**隐蔽通道**（绕过正常安全机制的非法信息传递路径），系统结构化为关键和非关键部分
- **第 5 级**：引入**访问监控器**（仲裁所有访问，本身抗篡改且足够小可分析和测试）

### 2. 安全风险管理

#### 风险评估定义
信息安全风险 = **脆弱性**被**威胁**利用后对**资产**造成的负面影响。
风险评估 = 依据技术标准，对信息系统的脆弱性、威胁和影响进行科学评价。

#### 风险评估 5 个基本要素及关系
核心逻辑链：
```
业务战略 →依赖→ 资产 →拥有→ 资产价值 →导出→ 安全需求 →被满足→ 安全措施
                ↑                                              ↓
             暴露                                            抗击
                |                                              ↓
             脆弱性 ←利用← 威胁 →演变→ 安全事件 →可能诱发→ 残余风险
```

| 要素 | 说明 |
|------|------|
| **资产** | 对组织有价值的信息或系统，资产价值取决于对业务的重要性 |
| **脆弱性** | 资产本身的弱点，可被威胁利用。**单独不造成损失** |
| **威胁** | 可能对资产造成破坏的因素或事件（人为有意/无意、环境因素） |
| **风险** | 威胁利用脆弱性造成损失的可能性 |
| **安全措施** | 抗击威胁、降低风险的手段，有成本 |

#### 脆弱性的重要特征（高频考点）
- 脆弱性是资产**本身固有**的，但**单独不会造成损失**
- **必须被威胁利用才会造成伤害**
- 没有安全威胁的脆弱性可以不实施保护措施，但必须记录
- **不正确或无效的安全措施本身也可能成为脆弱性**

> 类比：门锁坏了（脆弱性），没人知道（无威胁）暂时不丢东西；小偷发现了这个弱点（威胁利用脆弱性）就形成风险。修好门锁（安全措施）降低风险，但窗户还能被撬（残余风险）。

### 3. 残余风险（核心概念）
**风险不可能也没必要降为零**，实施安全措施后仍有残余风险。残余风险两部分来源：
1. **安全措施不当或无效** → 需继续控制
2. **综合考虑安全成本与资产价值后有意不控制** → 可接受

> 任何系统都有脆弱性，安全措施只能降低风险不能完全消除。残余风险需密切监视，可能诱发新的安全事件。

### 4. 风险评估的形式与准备
**2 种形式**：
- **自评估**：系统拥有者自己评估
- **他评估**：上级主管机关发起的强制性检查

**评估前 5 项准备**：确定评估范围 / 确定评估目标 / 建立组织结构（管理层+业务骨干+IT 人员）/ 建立评估方法 / 获得最高管理者批准。

### 5. 资产估价的要点
- **不是按账面价格**，而是按**对业务的安全重要性**估价
- 根据资产损失所引发的**潜在商务影响**来决定
- 通过考察**保密性、完整性、可用性**来反映资产价值

## 二、顾问指引（真实项目 AI 怎么用）

1. **等级定级**：做系统安全设计先定保护等级。一般业务系统 2 级（审计保护），涉及重要数据/金融 3 级起（强制访问控制）。定级决定后续投入。
2. **风险评估流程**：先盘资产（按业务重要性而非账面价）→ 找脆弱性 → 识别威胁 → 评估风险 → 选安全措施。提醒脆弱性单独无害，要结合威胁看。
3. **残余风险必须显式记录**：不能假装风险已清零。明确标注"这部分有意未控制（成本考量，可接受）"和"这部分需继续控制"。
4. **安全措施本身要审查**：不当的措施（如错误的防火墙规则、过弱的密钥策略）可能成为新的脆弱性，评估时要把现有措施也当资产弱点查。
5. **成本权衡**：安全投入要和资产价值匹配。给低价值资产上 5 级保护是浪费；给高价值资产只上 1 级是失职。

## 三、常见误区（AI 自检红线，来自真实学习错题）

- ❌ **残余风险只归因于"措施不当"** → 教材明确两部分：措施不当或无效（需继续控制）+ **成本与资产价值综合考虑后有意不控制**（可接受）。"没必要降为零"恰恰包含成本考量。
- ❌ **说残余风险"不可能降为零是因不存在没风险的资源"虽对但不完整** → 完整原因：任何系统都有脆弱性，安全措施只能降低不能消除；且成本考量下也没必要完全消除。
- ❌ **把第 3 级分界点记错** → 第 3 级是分界点（自主→强制访问控制）。1-2 级自主，3-5 级加强制。
- ❌ **脆弱性说成"单独会造成损失"** → 脆弱性单独不造成损失，必须被威胁利用才会形成风险。
- ❌ **资产估价按账面价格** → 应按对业务的安全重要性（潜在商务影响），通过保密性/完整性/可用性反映。
- ❌ **遗漏"无效安全措施也是脆弱性"** → 不正确或无效的安全措施本身可能成为新的脆弱性。
