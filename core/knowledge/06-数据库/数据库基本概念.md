## 一、核心知识体系

### 1. 基本概念辨析
| 概念 | 含义 |
|------|------|
| 数据 | 描述事物的符号记录（如 37.5） |
| 信息 | 有特定释义/意义的数据（如 37.5°C = 发烧） |
| DB | 统一管理、长期存储、有组织的相关数据集合 |
| DBMS | 数据库系统的**核心软件**，OS 之上管理数据 |
| DBS | 采用数据库技术的计算机系统（广义含 DBMS） |

关系：**DBS ⊃ DBMS ⊃ DB**，DBMS 是核心。

### 2. 数据管理技术 3 阶段
| 阶段 | 特征 | 缺点 |
|------|------|------|
| 人工管理 | 数据程序一一对应、不保存 | 依赖强、冗余 |
| 文件系统 | 可长期保存、按文件名访问 | **3 大缺点**（下） |
| 数据库系统 | 充分共享、与应用高度独立 | — |

**文件系统 3 大缺点**：① 数据冗余 ② 数据不一致性 ③ 数据孤立（联系弱）。
> 因果：冗余是不一致的根因；孤立靠数据模型描述联系解决。

### 3. 数据模型三要素
- **数据结构**：对象类型集合，静态特性（≈ 建表字段类型）
- **数据操作**：检索/插入/删除/修改，动态特性（≈ SQL）
- **数据的约束条件**：完整性规则集合，保证数据正确、有效、相容（≈ PK/NN/FK）

**3 代数据库**：1 代层次/网状（网状 ⊃ 层次）→ 2 代关系（表格）→ 3 代面向对象/XML/NoSQL

### 4. DBMS
- **6 大功能**：数据定义(DDL) / 数据库操作(DML) / 运行管理 / 数据组织存储 / 建立维护 / 其他
- **3 大特点**：数据结构化统一管理 / 较高数据独立性 / 数据控制功能
- **数据控制 4 项**：
  | 控制 | 防范 |
  |------|------|
  | 安全性 Security | 不合法使用致泄露/破坏（权限） |
  | 完整性 Integrality | 加入不符合语义的数据 |
  | 并发控制 | 多用户同时操作同一数据混乱 |
  | 故障恢复 | 故障后恢复；**原理 = 建立冗余数据** |

### 5. 三级模式 + 两级映象（核心）
- **三级模式**：
  - **外模式**（用户模式/子模式）= 用户接口，用户实际操作的层
  - **概念模式**（模式）= 全部数据逻辑结构，只涉及"型"，不涉存储（→ 物理独立性）
  - **内模式**（存储模式）= 物理结构和存储方式
- **两级映象**：
  | 映象 | 保证的独立性 |
  |------|------------|
  | 外模式/概念模式映象 | **逻辑数据独立性**（概念模式变→改映象→外模式/应用不变） |
  | 概念模式/内模式映象 | **物理数据独立性**（内模式/存储变→改映象→概念模式不变） |

> 一句话：数据按**外模式**给用户、按**内模式**存磁盘、**概念模式**是中间连接；两级映象使任一级改变不牵制另一级 = 数据独立性。

## 二、顾问指引（真实项目 AI 怎么用）

- 用户问"数据独立性/三级模式"：讲清两级映象各自保证什么，用"换存储=物理、改表结构=逻辑"举例
- 用户问"为什么改存储 SQL 不用动"：解释应用操作的是外模式，内模式变更被映象吸收
- 用户问 DB 选型/NoSQL：关联"3 代数据库"讲清关系型 vs NoSQL 的取舍

---

## 三、常见误区（AI 自检红线）

- ❌ **两级映象方向搞反**：外/概映象 = **逻辑**独立性，概/内映象 = **物理**独立性（不是反过来）
- ❌ **以为 SQL 操作内模式**：应用操作的是**外模式**，内模式是物理存储，应用不直接碰
- ❌ **混淆完整性 vs 并发控制**：完整性 = 防不符语义的数据；并发控制 = 防多用户同时改混乱
- ❌ **故障恢复原理说成"备份"**：教材原意是"**建立冗余数据**"（每条信息可用别处冗余重构）
