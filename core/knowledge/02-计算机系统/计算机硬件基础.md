## 一、核心知识体系

### 1. 冯·诺依曼架构与五大部件
计算机至今绝大多数仍遵循冯·诺依曼架构：**程序与数据存放在同一存储器中，由 CPU 统一处理**。

| 部件 | 职责 | 关系 |
|------|------|------|
| 输入设备 | 把外部信息送进内存（键盘、鼠标） | → 内存 |
| 存储器（内存） | 存放**正在运行的程序和数据** | CPU 直接读写 |
| 运算器 ALU | 算术与逻辑运算 | 与控制器合 = CPU |
| 控制器 CU | 解读指令、发控制信号 | 与运算器合 = CPU |
| 输出设备 | 把结果送出（显示器） | ← 内存 |

> **关键数据流向**：输入 → 内存 ↔ CPU → 内存 → 输出。CPU 不直接读硬盘，硬盘数据先加载进内存。

### 2. CPU 的工作循环
**取指(Fetch) → 译码(Decode) → 执行(Execute)**，无限重复。
- 程序计数器（PC, Program Counter）指向**下一条**指令地址
- ALU 做运算，CU 发信号，寄存器是 CPU 内部最快最小的存储

### 3. 存储层次（快/小/贵 → 慢/大/廉）
寄存器 → L1 Cache → L2 Cache → L3 Cache → 内存 → 硬盘

### 4. Cache 与局部性原理（高频考点）
Cache 存在的根本依据 = **局部性原理**：
| 类型 | 含义 | 典型例子 |
|------|------|---------|
| 时间局部性 (Temporal) | 刚访问的数据很快还会再访问 | 循环里的计数变量 i |
| 空间局部性 (Spatial) | 被访问数据附近的数据很快也会被访问 | 顺序遍历数组 |

Cache 加载一个数据会把它附近的数据一起加载——所以访问数组的下一个元素时数据已在 Cache 中，无需再等内存。

### 5. CISC vs RISC（高频对比）
| | CISC（复杂指令集） | RISC（精简指令集） |
|---|---|---|
| 全称 | Complex Instruction Set Computer | Reduced Instruction Set Computer |
| 思路 | 一条指令做很多事 | 一条指令只做一件事，但做得快 |
| 指令数/长度 | 多、变长 | 少、固定长度 |
| 代表 | x86（Intel/AMD） | ARM（手机、Apple M） |
| 功耗 | 高 | 低 |
| 典型用途 | 桌面/服务器 | 移动/嵌入式 |

> **本质区别 = 指令设计哲学**。功耗低是**结果**（指令简单→电路简单→耗电少），不是本质原因。

### 6. 总线
**总线（Bus）**= 所有部件共享的公共通信通道，解决"部件两两相连、线太多"问题。代价：同一时刻只能一对设备通信。

| 总线类型 | 传什么 |
|---------|--------|
| 数据总线 | 实际数据 |
| 地址总线 | 要访问哪个内存地址 |
| 控制总线 | 读/写/中断等控制信号 |

**地址总线宽度决定最大寻址空间**：32 根线 → 2³² 地址 → 4GB。

### 7. 计算机两层结构
- **核心层**：CPU + 内存，总线直连高速通信
- **外围层**：硬盘、网卡、键盘等外设，需 I/O 控制器当中间人

> 内存属于冯·诺依曼五大部件中**独立的核心部件**，不是外设。

### 8. 四种 I/O 控制方式（CPU 参与度递减，效率递增）
| 方式 | CPU 参与度 | 关键点 |
|------|-----------|--------|
| 程序查询 | 全程盯着问 | CPU 干等，最差 |
| 中断 (Interrupt) | 不等，但数据要经 CPU 中转 | 外设完成后主动通知 CPU |
| DMA (Direct Memory Access) | 几乎不参与 | **数据直达内存，不经 CPU**；前提是多了 DMA 控制器芯片接管总线控制权 |
| 通道 (Channel) | 完全不管 | 专用 I/O 处理器，能执行一串 I/O 指令，主要在大型机 |

### 9. 流水线技术
核心思路：各阶段**并行**，像工厂流水线。

**计算公式**（m 条指令，n 个阶段，每阶段 t）：
- 不用流水线：`m × n × t`
- 用流水线：`n×t + (m-1)×t`
- 加速比 = 不用流水线时间 / 用流水线时间

**三种风险**：
| 风险 | 原因 | 例子 |
|------|------|------|
| 结构风险 | 抢同一硬件资源 | 取指和执行同时要访问内存 |
| 数据风险 | 后指令要用前指令还没算完的结果 | `a=b+1; c=a+2;` |
| 控制风险 | 分支跳转导致后面指令可能白执行 | if/else |

### 10. 计算机语言三代
| | 机器语言 | 汇编语言 | 高级语言 |
|---|---|---|---|
| 形式 | 0 和 1 | 英文助记符（MOV/ADD） | 接近人类语言 |
| CPU 直接执行 | ✅ | ❌ 需汇编器(Assembler) | ❌ 需编译器/解释器 |
| 可移植性 | ❌ | ❌ | ✅ |

> **不可移植的根因**：每种 CPU 架构有自己的指令集（ISA, Instruction Set Architecture），同一操作在不同架构上编码完全不同。换 CPU = 换架构（不是换物理芯片），同架构可移植。

### 11. 编译 vs 解释
| | 编译 (Compilation) | 解释 (Interpretation) |
|---|---|---|
| 方式 | 一次性全部翻译成机器码 | 一边翻译一边执行 |
| 产物 | 生成独立可执行文件 | 不生成独立文件 |
| 速度 | 执行快 | 执行慢 |
| 代表 | C、C++ | Python、JavaScript |

### 12. Java 的字节码（特例，常考）
Java 是**混合模式**：源码 →（编译）→ 字节码 →（JVM 解释）→ 机器码。
- 字节码**不是任何真实 CPU 的指令**，是给 JVM 这个"虚拟 CPU"设计的
- 同一份字节码在不同架构的 JVM 上都能跑 = "一次编写，到处运行"

### 13. 跨平台策略的本质对比
跨平台的核心问题：**架构差异在哪一层被消化**。
| 语言 | 谁消化架构差异 |
|------|--------------|
| C/C++ | 开发者层（开发者多平台分别编译） |
| Java | JVM 层（编译一次，JVM 翻译） |
| Python/JS | 解释器层（分发源码，运行时翻译） |

> **关键**：翻译策略不是随意选的，是**语言设计目标的必然结果**——C 的低级特性（指针、手动内存管理）只能编译成机器码；Python 的高级特性（动态类型）更适合解释执行。

### 14. 翻译程序三兄弟
| 工具 | 翻译对象 | 方式 |
|------|---------|------|
| 汇编器 Assembler | 汇编语言 → 机器语言 | 一一对应 |
| 编译器 Compiler | 高级语言 → 机器码/字节码 | 一次性翻完 |
| 解释器 Interpreter | 高级语言 → 机器码 | 逐行翻译执行 |

## 二、顾问指引（真实项目里 AI 怎么用这些知识）

- **用户问"为什么换更快 CPU 整体没快几倍"** → 用阿姆达尔定律思路（关联到 2.9）或局部性原理解释瓶颈
- **用户问"为什么手机用 ARM"** → 讲 CISC/RISC 设计哲学差异，强调功耗是结果不是原因
- **用户问"为什么程序跑起来前要编译/打包"** → 关联编译/解释/字节码三种翻译路径
- **用户问"为什么 32 位系统只能用 4GB 内存"** → 从地址总线宽度（2³²）解释，不是硬盘不够
- **用户问 Docker/虚拟机是否同一层** → 强调都用虚拟内存机制（关联 OS 章节），但层级不同
- **讨论 API/接口设计** → 可关联"构件的标准化接口"概念（内部实现隐藏，只暴露契约）

## 三、常见误区（AI 自检红线，来自真实学习错题）

- ❌ **把功耗说成 CISC/RISC 的本质区别** → 功耗低是 RISC 指令简单的**结果**，本质是指令设计哲学
- ❌ **以为 CPU 直接读硬盘** → 硬盘数据先加载进内存，CPU 只从内存取
- ❌ **中断方式"只有读没有存"** → 中断方式下数据**读入和写出都要经过 CPU 中转**
- ❌ **把"字"当固定单位** → 字(Word)大小取决于 CPU 位数（32 位 CPU 一字=4 Byte，64 位 CPU=8 Byte）；字节(Byte, 8 bit)才是最小实用单位
- ❌ **认为 Java 编译成"机器码"** → Java 编译成**字节码**，再由 JVM 解释/编译为机器码
- ❌ **把跨平台差异归因为"语言复杂度"** → 本质是**架构差异在哪一层被消化**（开发者/JVM/解释器）
- ❌ **混淆流水线加速比与阿姆达尔定律** → 流水线算的是"指令序列并行节省的时间"；阿姆达尔算的是"换硬件后整体加速"
- ❌ **"32GB 内存需要 35 根地址线"说成精确要求** → 2³⁵=32GB 是**最少**需要，现代 CPU 地址线远多于此（多余留给扩展/映射）
