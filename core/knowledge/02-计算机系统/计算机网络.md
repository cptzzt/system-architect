## 一、核心知识体系

### 1. 为什么分层
网络通信极其复杂（网线/Wi-Fi、路由转发、协议封装……）。分层模型让每层只管自己的事、给上一层提供服务、用下一层的服务。

### 2. OSI 七层 vs TCP/IP 四层（高频考点）
| OSI 七层 | 职责 | TCP/IP 四层 | 协议例子 |
|---------|------|------------|---------|
| 7 应用层 Application | 用户直接接触的协议 | 应用层 | HTTP、FTP、SMTP、DNS |
| 6 表示层 Presentation | 数据格式转换、加密 | （合并到应用层） | SSL/TLS、JPEG |
| 5 会话层 Session | 管理通信会话 | （合并到应用层） | — |
| 4 传输层 Transport | 端到端数据传输保障 | 传输层 | **TCP、UDP** |
| 3 网络层 Network | 跨网络的路由和寻址 | 网际层 | **IP**、路由器 |
| 2 数据链路层 Data Link | 同一网络内的帧传输 | 网络接口层 | MAC 地址、交换机 |
| 1 物理层 Physical | 比特流在物理介质传输 | （合并到网络接口层） | 网线、光纤、Wi-Fi |

> 两个模型都要记，实际互联网以 **TCP/IP 四层**为主。

### 3. 数据封装与拆包（必考流程）
**发送端**从上到下逐层封装，**接收端**从下到上逐层拆包：
```
应用层(产生 HTTP 数据) → 表示层(TLS 加密) → 会话层
→ 传输层(加端口号) → 网络层(加 IP) → 数据链路层(加 MAC) → 物理层(电信号发出)
```
> **封装动作从传输层开始**，应用层是数据源头不封装。每层都经过，没有跳过。

### 4. IP 地址
- **IPv4**：32 位，约 43 亿个，已经不够用
- **IPv6**：128 位，数量多到用不完
- **公网 IP**：全球唯一，可被互联网直接访问
- **私有 IP**：只在局域网内有效。私有范围：
  - `10.x.x.x`（A 类）
  - `172.16.x.x ~ 172.31.x.x`（B 类）
  - `192.168.x.x`（C 类）
- **关键**：路由器**绝不**把私有地址转发到公网

### 5. NAT（Network Address Translation，网络地址转换）
- 工作在**网络层**，**双向**转换：发请求时私→公，收响应时公→私
- 一个公网 IP 给多台设备共享，解决 IPv4 不够用
- 路由器从运营商获得公网 IP（IPv4 紧缺时运营商用 CGNAT 让多户共享一个公网 IP）

### 6. MAC 地址 vs IP 地址（易混）
| | IP 地址 | MAC 地址 |
|---|---|---|
| 全称 | Internet Protocol Address | Media Access Control Address |
| 性质 | 逻辑地址（可改） | 物理地址（网卡出厂烧录） |
| 长度 | 32 位（IPv4） | 48 位 |
| 决定 | 送到哪个**网络** | 送到网络里的哪块**网卡** |
| 类比 | 邮寄地址（可搬家） | 身份证号（永远不变） |

### 7. TCP vs UDP（高频对比）
| | TCP（传输控制协议） | UDP（用户数据报协议） |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠（确认、重传） | 不可靠（发了不管） |
| 速度 | 较慢 | 快 |
| 适用 | 网页、文件、邮件 | 视频直播、游戏、DNS 查询 |

### 8. TCP 三次握手（建立连接）
```
客户端                       服务器
  │─── SYN ──────────────►│   第1次：客户端说"我要连你"
  │◄── SYN+ACK ──────────│   第2次：服务器说"收到，我也准备好"
  │─── ACK ──────────────►│   第3次：客户端说"确认，开始传"
```
> **为什么三次不是两次**：防止"过期请求"导致错误建立连接（两次无法确认客户端的接收能力）。

### 9. TCP 四次挥手（断开连接）
```
客户端                       服务器
  │─── FIN ──────────────►│   客户端：我说完了
  │◄── ACK ───────────────│   服务器：收到
  │◄── FIN ───────────────│   服务器：我也说完了
  │─── ACK ──────────────►│   客户端：收到，再见
```
> **为什么四次不是三次**：服务器收到 FIN 后**可能还有数据没发完**，ACK 和 FIN 不能合并（全双工，双方各自关闭）。如果服务器恰好没数据，实际也可能合并成三次。

> SYN/ACK/FIN 是 TCP 包头里的**标志位**（信号，不是数据），每次来回是各自独立的 TCP 包。

### 10. DNS（Domain Name System，域名系统）
域名 → IP 地址的翻译服务。没有 DNS 就得记住每个网站的 IP。

### 11. HTTP vs HTTPS
| | HTTP | HTTPS |
|---|---|---|
| 全称 | HyperText Transfer Protocol | HTTP + SSL/TLS |
| 传输 | 明文（中间人可偷看篡改） | 加密（中间人只看到乱码） |
| 端口 | 80 | 443 |

> HTTPS = HTTP + SSL/TLS（Secure Sockets Layer / Transport Layer Security）加密。考试只需知道这一点，握手细节不深入。

### 12. 子网掩码（高频计算）
子网掩码区分 IP 的"网络部分"和"主机部分"。
- 不只是 255 和 0，可以是 254/252/248 等（左边连续 1，右边连续 0）
- `255.255.255.0`：前 3 段是网络号，最后 1 段是主机号，最多 254 台设备（0 和 255 保留）
- **CIDR 表示法**：`/24` 等同于 `255.255.255.0`，`/16` 等同于 `255.255.0.0`

**两个独立机制（易混）**：
- 子网掩码决定"是否**同一子网**"
- 私有 IP 范围决定"能不能**上公网**"
- "发给路由器" ≠ "上公网"——路由器发现目标是私有地址且本地无对应子网，会**直接丢弃**，不转发到公网

### 13. 常用端口号
| 端口 | 协议 | 用途 |
|------|------|------|
| 80 | HTTP | 网页 |
| 443 | HTTPS | 加密网页 |
| 22 | SSH | 远程登录 |
| 21 | FTP | 文件传输 |
| 53 | DNS | 域名解析 |
| 3306 | MySQL | 数据库 |

> 端口号区分同一台机器上的不同服务。

## 二、顾问指引（真实项目里 AI 怎么用这些知识）

- **用户问"浏览器输入网址到页面显示经历了什么"** → 走完整流程：DNS 解析→TCP 三次握手→发 HTTP 请求→服务器返回→TCP 四次挥手；数据经所有层封装/拆包
- **用户问"localhost 走不走 DNS"** → localhost 不走 DNS，直接映射 127.0.0.1
- **用户问"内网两台机器怎么通信、会不会跑到邻居"** → 解释每家路由器有独立公网 IP，各自管私有网络，物理隔离；同子网直接通信，不同子网发路由器
- **用户讨论 HTTPS 证书/部署** → 关联 SSL/TLS 加密、443 端口；生产环境强制 HTTPS
- **用户配置网络/排错** → 用子网掩码/CIDR 判断是否同一子网，关联"路由器对私有地址不转发到公网"
- **用户选 TCP/UDP** → 按可靠 vs 实时权衡：网页/文件/邮件用 TCP；视频直播/游戏用 UDP

## 三、常见误区（AI 自检红线，来自真实学习错题）

- ❌ **封装只列 3 层** → 完整流程要经过**所有 7 层**（应用→表示→会话→传输→网络→数据链路→物理），没有跳过
- ❌ **把"封装"说成应用层也封装** → **封装从传输层开始**，应用层是数据源头不封装
- ❌ **把 SSL/TLS 等同于 HTTPS** → SSL/TLS 是**加密协议**，HTTPS = HTTP + SSL/TLS，SSL/TLS 本身不是 HTTP
- ❌ **子网掩码"限死 192.168"** → 子网掩码决定切在哪，网络号取决于**自己的 IP**；`255.0.0.0` 技术上也能用在 192.168 上（只是无实际意义）
- ❌ **"发给路由器"= "上公网"** → 路由器对私有地址且本地无对应子网的请求**直接丢弃**，不转发到公网
- ❌ **混淆子网掩码和私有 IP 范围的作用** → 子网掩码管"是否同子网"，私有 IP 范围管"能不能上公网"，作用在不同层面不矛盾
- ❌ **TCP 三次握手用两次解释** → 三次的根本原因是防止过期请求 + 双向确认接收能力
- ❌ **四次挥手说"必须四次"** → 实际上服务器恰好没数据时也可能合并成三次；标准是四次因为全双工
