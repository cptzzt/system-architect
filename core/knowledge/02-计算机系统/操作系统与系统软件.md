## 一、核心知识体系

### 1. 操作系统的定位与职责
操作系统（OS, Operating System）夹在硬件和应用之间，核心职责四个字：**资源管理**。
- 管进程（谁用 CPU、用多久）
- 管内存（谁用哪块、不够怎么办）
- 管文件（数据怎么存、怎么找）
- 管设备（外设如何分配给各程序）

### 2. 进程 vs 程序
- **程序**：存在硬盘上的静态代码（如 `chrome.exe`）
- **进程**：程序被加载到内存运行起来。同一程序可同时跑多个进程

### 3. 进程三状态（高频考点）
| 状态 | 含义 | 转换条件 |
|------|------|---------|
| 就绪 (Ready) | 准备好运行，等 CPU 时间片 | 时间片用完 ← 运行；I/O 完成 ← 阻塞 |
| 运行 (Running) | 正在用 CPU | 获得 CPU ← 就绪；等 I/O → 阻塞 |
| 阻塞 (Blocked) | 等某件事（硬盘、网络） | 运行中等 I/O → 阻塞；完成后回**就绪**（不直接回运行） |

> 阻塞完成后回**就绪**，不是直接回运行——必须重新排队等 CPU。

### 4. 并发 vs 并行（高频易混）
| | 并发 (Concurrency) | 并行 (Parallelism) |
|---|---|---|
| 实现 | 单核 CPU 快速切换时间片 | 多核 CPU 每核真同时跑 |
| 本质 | 看起来同时 | 真正同时 |
| 常态性 | 日常电脑主要靠并发 | 并行是少数（核数有限） |

> 4 核 CPU 同一时刻最多 4 个进程真正并行，其余都在排队（就绪或阻塞）。

### 5. 进程调度算法
| 算法 | 全称 | 思路 | 缺点 |
|------|------|------|------|
| FCFS | First Come First Served | 先来先服务 | 短任务被长任务堵 |
| SJF | Shortest Job First | 短作业优先 | 长任务可能**饿死** |
| RR | Round Robin | 时间片轮转 | — |
| 优先级调度 | — | 高优先级先跑 | 低优先级可能饿死 |

"饿死"（Starvation）= 某进程一直得不到 CPU，永远无法执行。

### 6. 前趋图（Precedence Graph，真题高频）
- 是一个**有向无环图（DAG）**，描述进程之间执行的先后顺序
- `(Pi, Pj)` 表示 Pi 必须在 Pj 之前完成
- 考法：给图选前趋关系，或给关系选图——本质就是读图

### 7. 进程同步：信号量与 PV 操作（必考）
冲突场景：多进程同时改同一资源（如银行余额）会导致数据错乱。

| 机制 | 含义 |
|------|------|
| 互斥锁 (Mutex, Mutual Exclusion) | 同一时刻只允许一个进程访问；是信号量计数器=1 的特例 |
| 信号量 (Semaphore) | 通用计数器工具；N 值允许 N 个进程同时访问 |
| PV 操作 | 操作信号量的动作：P=申请资源(计数器-1)，V=释放资源(计数器+1) |

> **三者是一层套一层**：信号量是计数器工具 → 互斥锁是信号量的特例 → PV 操作是操作信号量的具体动作。

### 8. 虚拟内存（核心概念）
操作系统给每个进程一个**独立的虚拟地址空间**，进程以为自己独占整个内存。通过**页表（Page Table）**把虚拟地址翻译成真实物理地址。
- 进程 A 和 B 都以为自己从 0x0000 开始，实际映射到不同物理地址
- **天然隔离**：互相看不到对方内存（容器/虚拟机都依赖此机制）
- 虚拟空间可远大于物理内存（64 位 CPU 地址线 2⁴⁸ 编号范围约 256TB），但大部分编号是空的没映射——"门牌号排到 10000 不代表有 10000 栋房子"

### 9. 分页机制
- **页（Page）**= 虚拟内存的切块；**页框（Page Frame）**= 物理内存的切块；大小相同（通常 4KB）
- 页表记录：虚拟页号 → 物理页框号（一对一映射，偏移量不变，只替换页号）
- **缺页中断**：进程访问的虚拟页不在物理内存（在硬盘交换区），触发中断，OS 从硬盘加载该页

### 10. 页面置换算法（高频对比）
内存满了要淘汰谁？
| 算法 | 全称 | 思路 | 特点 |
|------|------|------|------|
| OPT | Optimal | 淘汰最远未来才用的 | 理论最优，**无法实现**（不能预知未来） |
| FIFO | First In First Out | 淘汰最早进来的 | 可能踢掉正在用的 |
| LRU | Least Recently Used | 淘汰最久没被访问的 | **实际常用**，与 Cache 局部性原理相关 |
| CLOCK | — | LRU 简化版：循环链表+引用位，灯亮跳过灯灭淘汰 | 折中方案 |

### 11. 死锁四条件（必考）
**四个必要条件**（同时满足才死锁，打破任意一个即可预防）：
1. **互斥**：资源同一时刻只能被一个进程使用
2. **占有并等待**：拿着已有资源，同时等新的
3. **不可剥夺**：不能强行抢别人的
4. **循环等待**：A 等 B，B 等 C，C 等 A

**应对策略**：预防（破坏条件之一）/ 避免（银行家算法，分配前先检查）/ 检测+恢复 / 鸵鸟策略（忽略，工程中常见）。

### 12. 文件存储分配方式
| 方式 | 特点 |
|------|------|
| 连续分配 | 读写快，但产生碎片 |
| 链接分配 | 不怕碎片，**不能随机访问**（像单向链表必须从头遍历） |
| 索引分配 | 索引块记录位置，**支持随机访问**；UNIX/Linux 方式 |

- **随机访问** = 直接跳到任意位置，不需从头遍历（连续/索引分配都支持）
- **碎片** = 硬盘空间被分割成不连续小块，总空间够但放不下大文件

### 13. 中间件（Middleware）
位于 OS 之上、应用之下的系统软件，帮不同技术栈的应用通信和共享资源。
- 核心价值：避免 N 个应用之间两两写通信逻辑（C(N,2) 套），用中间件统一对接只需 N 套
- 常见类型：数据库中间件、消息中间件（MOM, 如 RabbitMQ/Kafka）、通信中间件（gRPC/REST）、事务中间件、安全中间件

### 14. 软件构件（Software Component）
可重用、可替换、独立的软件单元，像乐高积木拼装成应用。
- 关键特征：**可重用 / 可替换 / 独立（接口对外，实现隐藏）/ 标准化接口**
- 常见技术：EJB、COM/DCOM、CORBA、Web Service、微服务

### 15. 构件 vs 中间件
- 构件 = **积木块**（做功能用的）
- 中间件 = **粘合剂**（让积木块之间通信协作）
- 应用 = 构件 + 中间件 + OS（底座）

## 二、顾问指引（真实项目里 AI 怎么用这些知识）

- **用户问容器/虚拟机/进程区别** → 都用虚拟内存机制，但层级不同：进程是基本单位，容器是一组被隔离的进程，虚拟机跑完整 Guest OS
- **用户问"内存不够系统为啥卡/崩"** → 解释交换区：内存满→LRU 等算法挑页写到硬盘→腾空间加载新页；频繁换页=抖动(Thrashing)；硬盘满→交换区写不进→Linux OOM Killer 杀进程/Windows 弹警告
- **用户问并发与多线程同步** → 互斥锁/信号量/PV 操作的层级关系，强调互斥锁是信号量特例
- **讨论微服务/SOA 通信** → 关联中间件概念（避免 N×N 复杂度）和构件的标准化接口
- **讨论"前后端分离、API 设计"** → 关联构件"内部实现隐藏，只暴露标准化接口"（前端调 `GET /api/xxx` 不需要知道后端用什么数据库/查询逻辑）

## 三、常见误区（AI 自检红线，来自真实学习错题）

- ❌ **阻塞完成直接回"运行"** → 阻塞完成后回**就绪**，要重新排队等 CPU
- ❌ **把并发等同于并行** → 并发是单核快速切换（看起来同时），并行是多核真同时；日常电脑主要靠并发
- ❌ **把页表当一对多映射** → 页表是虚拟页号→物理页框号的**一对一**映射，偏移量不变
- ❌ **认为虚拟内存是真实硬件** → 虚拟内存是 OS 制造的**假象**，靠页表翻译
- ❌ **把 256TB 虚拟地址空间当真实容量** → 是地址编号范围上限，大部分没映射、是空的
- ❌ **互斥锁和信号量并列说** → 互斥锁是信号量计数器=1 的**特例**，不是平行概念
- ❌ **链接分配"支持随机访问"** → 链接分配必须从头遍历，**不能随机访问**
- ❌ **碎片说成"空间不够"** → 是"空间被分割成不连续小块"，总空间够但放不下大文件
- ❌ **把跨表外码关联当"传递依赖"** → 传递依赖是**单表内** X→Y→Z（关联数据库章节）
- ❌ **构件与中间件混淆** → 构件是积木块（做功能），中间件是粘合剂（做通信）
