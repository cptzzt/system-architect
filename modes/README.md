# 模式清单

> 模式是 AI 这个架构师"戴上不同帽子"，**可选**，不是 skill 的主体。
> 用户不需显式切换模式——AI 根据用户问题和"用户上下文"自然匹配对应模式的行为指引。

## 模式触发（见 SKILL.md 行为路由表）

| 场景信号 | 模式 | 文件 |
|---------|------|------|
| "我的项目…"、问真实设计 | 架构顾问 | [架构顾问模式.md](架构顾问模式.md) |
| 备考=是、问考试/真题/论文 | 学习导师 | [学习导师模式.md](学习导师模式.md) |
| "A vs B 怎么选"、"评审方案" | 技术选型 | [技术选型模式.md](技术选型模式.md) |

## 默认

不确定/混合场景 → 默认通用架构师行为（SKILL.md 内核 + core/knowledge），不强制套某个模式。

## 扩展

用户可自建模式文件（如 `modes/代码评审模式.md`），在 SKILL.md 行为路由表加一行触发规则即可。模式之间互不污染，各管各的行为指引。
